# HZCU HPC Team 全站温暖编辑式视觉重建设计

日期：2026-08-10
状态：已确认

## 1. 目标与边界

将现有 HZCU HPC Team 网站重建为具有科技企业气质的温暖编辑式视觉系统，参考 Anthropic/Claude 的克制、思想感和出版物气质，同时保持高校高性能计算团队的学术可信度。

本项目仅重建设计表现，不改变现有素材和网站信息：

- 保留全部现有文字、图片、头像、作者档案、奖项、文章、菜单名称和目标地址。
- 不替换或编辑图片源文件，不改写内容，不新增虚构口号、数据、认证、客户或办公地点。
- 允许重排首页区块顺序、条目布局、网格列数和图片位置，以形成统一视觉节奏。
- 覆盖全站：首页、导航、页脚、People、成员详情、Post、Diary、Recruitment、Memory、Publication、Accomplishments、Contact 及文章详情。
- 仅提供暖色亮色主题，移除明暗模式切换。
- 完全采用二维设计，不使用 WebGL、Three.js、粒子、三维模型或持续运动装饰。

## 2. 技术方案

采用混合式 Hugo 定制：继续使用现有 Markdown、YAML Front Matter、作者档案、内容集合和 Hugo Blox 内容能力，在仓库内增加必要的本地模板覆盖、模块化 SCSS 和轻量 JavaScript。

选择该方案的原因：

- 纯 SCSS 覆盖受主题 DOM 限制，只能换肤，无法可靠重建区块结构。
- 完全自建主题需要重新实现分页、分类、搜索、图片处理等现成功能，范围和维护成本不合理。
- 混合式方案可以重建关键视觉结构，同时让后续维护人员继续只编辑 Markdown。

主题继续负责内容解析、分类、分页、图片处理和页面生成。本地覆盖仅承担导航、页脚、首页首屏、集合条目、People 卡片、列表外壳和文章外壳等影响设计结构的部分。实施时先查询 Hugo 模板查找链和已下载主题模块，再确定精确覆盖路径，不猜测主题文件名。

## 3. 设计原则

### 3.1 视觉语言

- 暖米白纸张背景、暖炭黑文字和陶土橙单一主强调色。
- 以排版、网格、留白、细边线和图像比例建立层级。
- 使用编辑式衬线标题与清晰的无衬线正文，强化研究出版物和科技品牌气质。
- 避免常见 SaaS 视觉：蓝紫渐变、霓虹、玻璃模糊、发光描边、厚阴影、胶囊按钮和大量圆角卡片。
- 不使用 emoji 作为界面图标；需要图标时沿用主题图标或使用同一套线性 SVG。
- 悬停状态不得导致布局位移。

### 3.2 UI/UX Pro Max 基线

- 正文文字对比度至少 4.5:1。
- 可点击和触控区域至少 44 × 44px。
- 键盘顺序与视觉顺序一致，所有功能可通过键盘操作。
- 提供清晰的 `:focus-visible` 状态和“跳至主要内容”链接。
- 移动端正文不低于 16px。
- 正文行高 1.7–1.8，长文阅读宽度约 68–72ch。
- 微交互控制在 150–300ms，进入使用 ease-out，退出使用 ease-in。
- 每个视口最多突出 1–2 处动画，不使用无限循环装饰动画。
- 完整支持 `prefers-reduced-motion`。
- 响应式图片使用 Hugo 生成多个尺寸，并输出 `srcset` 与 `sizes`。
- 固定导航和菜单明确设置层叠层级，不依赖 DOM 顺序。

## 4. 设计令牌

### 4.1 色彩

| 角色 | 色值 | 用途 |
| --- | ---: | --- |
| 页面背景 | `#F2EFE7` | 全站暖米白背景 |
| 次级背景 | `#E8E2D7` | 区块轻度区分和图片占位 |
| 主文字 | `#1F1E1A` | 标题、正文、导航 |
| 次级文字 | `#625E55` | 日期、标签、说明 |
| 边线 | `#C9C1B4` | 区块、导航和条目分隔 |
| 强边线 | `#8A8378` | 悬停和结构强调 |
| 陶土橙 | `#B95232` | 链接、编号、焦点和少量强调 |
| 深陶土橙 | `#8E3922` | 悬停或需要更高对比度的状态 |
| 鼠尾草绿 | `#788476` | 少量分类和辅助层次 |
| 反色背景 | `#24241F` | 必要的深色品牌区块 |
| 反色文字 | `#F2EFE7` | 反色背景上的文字 |

陶土橙不得大面积铺满页面，也不得作为状态的唯一提示；同时提供边线、下划线或文字变化。实施时以实际字号和背景进行 WCAG AA 对比度验证，若令牌组合不达标则向更深色方向调整。

### 4.2 字体

不依赖 Google Fonts 或其他远程字体 CDN，避免当前网络环境下加载失败和布局跳动。

```scss
--font-display:
  Georgia,
  "Songti SC",
  "STSong",
  "Noto Serif CJK SC",
  serif;

--font-body:
  -apple-system,
  BlinkMacSystemFont,
  "Segoe UI",
  "PingFang SC",
  "Hiragino Sans GB",
  "Microsoft YaHei",
  sans-serif;

--font-mono:
  "SFMono-Regular",
  Consolas,
  "Liberation Mono",
  monospace;
```

建议流式字号：

```scss
--text-xs: 0.75rem;
--text-sm: 0.875rem;
--text-base: clamp(1rem, 0.97rem + 0.12vw, 1.075rem);
--text-lg: clamp(1.125rem, 1.06rem + 0.25vw, 1.3rem);
--heading-sm: clamp(1.5rem, 1.25rem + 1vw, 2.15rem);
--heading-md: clamp(2.2rem, 1.55rem + 2.8vw, 4.5rem);
--heading-hero: clamp(3.7rem, 2.3rem + 6.2vw, 8.5rem);
```

首屏英文标题可使用负字距；正文和中文不强制增加或压缩字距。英文界面标签可使用大写和宽字距。

### 4.3 间距与形状

```scss
--space-1: 0.375rem;
--space-2: 0.75rem;
--space-3: 1rem;
--space-4: 1.5rem;
--space-5: 2rem;
--space-6: clamp(2.5rem, 5vw, 5rem);
--space-7: clamp(4rem, 8vw, 8rem);
```

- 全站最大内容宽度约 1440px。
- 页面水平留白：手机 20px、平板 32px、桌面 48–72px。
- 索引页使用 12 栏网格，文章使用独立窄阅读栏。
- 默认无阴影；普通元素圆角 0–4px，图片最多使用轻微 2px 圆角。
- 使用 1px 边线和留白区分层级，不使用卡片套卡片。

## 5. 页面设计

### 5.1 全局导航

- 左侧显示现有网站名称或 Logo，右侧保留全部现有菜单。
- 使用暖米白背景和细底边线，不使用玻璃模糊或厚阴影。
- 当前页面通过陶土橙细线和文字状态标识，不使用胶囊按钮。
- 保留搜索功能，使用统一线性图标和可访问名称。
- 移除明暗模式按钮。
- 页面滚动后导航可以轻微压缩；动画约 220ms。
- 移动端使用至少 44px 的菜单按钮和全宽菜单面板，打开后不产生键盘陷阱。
- 添加“跳至主要内容”链接。

### 5.2 首页

#### 首屏

采用已确认的编辑式分屏：

- 左侧使用现有 `HZCU HPC Team` 标题和中文介绍。
- 右侧显示现有 `assets/media/banner.jpg`。
- 不新增宣传口号或修改文案。
- 桌面端比例约 52% / 48%，移动端改为文字在上、图片在下。
- 图片使用响应式尺寸和稳定焦点位置；窄屏使用宽高比而非固定高度。
- 标题、介绍、图片分三步进入，总时长约 650–800ms。

#### Introduction

- 保留当前 recruitment 集合和所有内容。
- 使用编辑目录结构，不使用统一圆角卡片阵列。
- 第一条作为较大的主条目，其余内容组成非对称网格或有序列表。
- 图片、日期、标题和摘要形成明确层级。
- 悬停仅改变边线、文字和图片透明度，不移动卡片。

#### Accomplishments

- 保留现有年份、奖项名称和日期。
- 使用纵向时间轴或编号档案结构。
- 年份采用大号编辑数字，条目用细线分隔。
- 陶土橙仅用于年份、编号或交互状态。

#### 结尾 CTA

- 保留现有 `Meet the team →` 文案和链接。
- 使用横跨容器的大字号文本链接，不改成通用圆角按钮。
- 悬停时箭头轻微平移、底线展开。

### 5.3 People 和成员详情

- 保留全部作者档案、头像、角色、社交链接和 `user_groups`。
- 每个成员分组成为独立编辑章节；分组名称必须与现有数据精确同步。
- 成员列表采用大头像与简洁文字，无浮层阴影。
- 桌面端 3–4 列，移动端根据宽度显示 1–2 列。
- 头像由 Hugo 生成响应式尺寸，不修改原文件。
- 姓名使用展示字体，角色使用正文小字。
- 社交链接使用统一线性图标和可访问名称。
- 成员详情使用人物档案结构：头像、姓名和角色组成页头，介绍位于窄阅读栏。

### 5.4 集合列表页

Post、Diary、Recruitment、Memory、Publication 等使用同一出版物索引语言：

- 顶部显示现有栏目名和介绍。
- 条目使用细线分隔，不默认放进圆角卡片。
- 有封面时使用图文网格；无封面时自动切换为完整纯文本版式，不显示空占位。
- 日期、标签和作者作为辅助元数据。
- Diary 保留内容语气，但不另建视觉系统。
- 分页使用文字和箭头，不使用厚重按钮。

### 5.5 文章与日记详情

- 文章头部由现有标题、日期、作者和标签构成。
- 保留主图比例、说明以及正文内所有图片、链接和文字。
- 正文宽度约 68–72ch，中文行高约 1.75。
- 统一标题、引用、列表、代码块和图片说明样式。
- 宽图可以适度超出阅读栏，但页面不得横向滚动。
- 主题已有的作者信息和相关文章继续保留，仅改变外观。

### 5.6 Accomplishments、Contact 与页脚

- Accomplishments 独立页沿用首页时间轴语言，完整显示现有内容。
- Contact 保留现有地址、联系方式、地图或表单配置，使用两栏编辑布局，移动端纵向排列。
- 页脚保留版权和许可信息，使用顶边线和大留白。
- 网站名称、菜单、版权形成三段式结构，移动端按可读顺序堆叠。
- 不新增无实际地址的社交图标。

## 6. 响应式规则

重点验收 375px、768px、1024px 和 1440px：

- 12 栏网格依次降为 6 栏、2 栏或单栏。
- 首屏在窄屏改为纵向，图片使用稳定宽高比。
- People 在手机显示 1–2 列，取决于实际可读宽度。
- 导航展开不遮挡焦点，不锁定键盘操作。
- 表格和代码块可局部横向滚动，页面主体不得横向溢出。
- 标题用 `clamp()` 缩放，长中文标题不得溢出。
- 图片生成多档尺寸并设置准确的 `srcset` 和 `sizes`。

## 7. 动效

采用适度二维品牌动效：

- 首屏标题、介绍和图片错开 70–110ms 进入。
- 仅使用 `opacity` 和 `transform`，避免布局重排。
- 区块滚动揭示使用原生 `IntersectionObserver`，位移不超过 12–18px，进入后停止观察。
- 每个视口最多突出 1–2 个关键区块。
- 链接下划线约 180ms；箭头位移约 200ms；图片变化约 250–300ms；导航压缩约 220ms。
- 不使用卡片缩放、滚动劫持、无限循环动画或三维视差。
- 无 JavaScript 时内容默认可见。

CSS 和 JavaScript 都检查 `prefers-reduced-motion`。减少动态模式下关闭揭示和图片视差，所有内容立即显示，滚动行为恢复为自动。

## 8. 文件边界

### 8.1 配置

预计调整 `config/_default/params.yaml`：关闭明暗切换，并调整与新视觉冲突的外观配置。保留搜索、菜单、SEO 和其他现有功能。

### 8.2 SCSS

将 `assets/scss/template.scss` 拆分为职责明确的模块；入口文件仅负责导入：

```text
assets/scss/
├── template.scss
├── abstracts/
│   ├── _tokens.scss
│   └── _mixins.scss
├── base/
│   ├── _reset.scss
│   ├── _typography.scss
│   └── _accessibility.scss
├── components/
│   ├── _navigation.scss
│   ├── _cards.scss
│   ├── _people.scss
│   └── _footer.scss
└── pages/
    ├── _home.scss
    ├── _list.scss
    └── _article.scss
```

实际模块可按主题 DOM 调查结果合并或增补，但必须保持职责单一，避免重新形成一个超大样式文件。

### 8.3 模板

在 `layouts/` 下仅覆盖影响结构的主题模板。精确路径在实施前通过 Hugo 模块缓存和模板查找链确定。覆盖优先级：导航和页脚、首页首屏、集合条目、People 卡片、列表与文章外壳。

### 8.4 JavaScript

增加一个小型本地脚本处理：

- 区块滚动揭示；
- 导航滚动状态；
- 极轻微的二维图片位移；
- 减少动态偏好检测。

不新增 npm、Vite、React、Three.js 或大型动画依赖。

## 9. 降级与错误处理

- JavaScript 关闭时，内容默认可见，链接和导航仍可使用。
- 图片缺失时隐藏破损装饰层，保留标题和文字布局。
- 无封面的内容条目自动使用纯文本样式。
- 不使用远程字体，因此字体网络失败不会破坏布局。
- 单个本地模板覆盖失配时应优先回退到 Hugo Blox 默认输出，而不是让构建失败。
- 不直接修改生成目录 `public/`；所有改动均在源文件中完成。

## 10. 验证和验收

1. 使用 Hugo Extended 0.135.0 完成生产构建，检查警告和无效引用。
2. 验证首页、People、成员详情、Post、文章详情、Diary、Accomplishments 和 Contact。
3. 检查 375px、768px、1024px 和 1440px，无页面级横向滚动。
4. 检查图片裁切、无封面条目、长中文标题和中英文混排。
5. 使用键盘完成导航、移动菜单和搜索操作，确认焦点可见且无键盘陷阱。
6. 检查标题层级、图片替代文本、图标可访问名称和触控目标。
7. 对主文字、次级文字、链接、焦点状态执行颜色对比度检查。
8. 分别检查正常动态、`prefers-reduced-motion` 和禁用 JavaScript状态。
9. 若浏览器驱动可用，对关键页面在四个目标宽度截图并进行视觉复核。
10. 只有构建、功能、可访问性和视觉检查均通过后，才视为完成。
